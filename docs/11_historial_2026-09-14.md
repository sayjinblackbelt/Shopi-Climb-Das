# Historial de mejoras — 14/09/2026

## Objetivo

Registrar las mejoras implementadas durante el ciclo del 14/09/2026 y los problemas encontrados durante las pruebas.

## Corrección crítica del flujo

Se corrigió el flujo principal de progresión de la campaña, incluyendo:

- avance entre fases;
- desbloqueo y selección de fases;
- continuación de la campaña;
- pausa con continuar, reiniciar, configuración y salir;
- recuperación tras Game Over y selección de fase;
- finalización de fase y acceso a la siguiente;
- protección contra la finalización prematura del Capítulo 1;
- finalización correcta de la campaña en la Fase 16.

La corrección fue probada y considerada funcional por el autor.

## Mejoras de gameplay — segundo prompt del día

Se ejecutó un nuevo ciclo de mejoras centrado en:

- sensación de movimiento;
- respuesta del salto;
- lectura de plataformas;
- ritmo de las fases;
- progresión de dificultad;
- interacción de cabezazo;
- feedback visual y sonoro;
- cámara;
- checkpoints;
- puntuación;
- identidad de los clientes;
- relación Shopi/Etvaldo;
- identidad de las entregas.

Los controles móviles existentes fueron preservados porque ya funcionaban bien.

## Código de Entrega

A partir de la Fase 6, cada entrega tiene un código simple, con un formato como:

`SHP-06-EDV-4721`

El objetivo es crear una sensación más realista de logística y entregas sin convertir el código en un sistema complejo.

El código puede aparecer al inicio/final de la entrega y ocasionalmente en etiquetas o elementos del escenario.

## Problema encontrado durante las pruebas

### Fase 11 — El Hospital

Se identificó un punto donde el salto entre dos partes de la fase **no es posible**.

Corrección prevista para el próximo ciclo:

1. reducir la distancia entre las dos partes; **o**
2. añadir un punto de apoyo/plataforma intermedia.

La corrección debe mantener el desafío, pero eliminar el bloqueo imposible.

## GitHub Pages

El portal del proyecto recibió un **contador global de visitantes**, independiente de la clasificación del juego.

La integración utiliza un servicio externo compatible con páginas estáticas, sin necesidad de un backend propio.
