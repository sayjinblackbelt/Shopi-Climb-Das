# Base44 — desenvolvimento do jogo

## Papel do Base44

O Base44 é a principal ferramenta utilizada para prototipagem e evolução do jogo Shopi.

O desenvolvimento segue um ciclo incremental:

**Ideia → Prompt → Geração → Teste → Feedback → Melhoria → Registro**

## Estado atual

O projeto evoluiu do MVP inicial para uma campanha com **6 fases jogáveis**, **3 níveis globais de dificuldade**, controles desktop/mobile, ranking, vidas, checkpoint e pontuação.

As seis fases foram testadas pelo autor até o final da campanha.

## Funcionalidades incorporadas

- movimentação do protagonista;
- salto;
- plataformas;
- escadas;
- obstáculos com comportamentos variados;
- vidas;
- checkpoint;
- pontuação;
- seis fases jogáveis;
- Shopi como protagonista;
- Etvaldo como ajudante recorrente;
- seis clientes/bosses;
- três níveis de dificuldade;
- controles por toque para celular;
- ranking de líderes;
- progressão da campanha.

## Dificuldade

Os níveis atuais são:

- Entrega Tranquila — ×1;
- Entrega Complicada — ×1,5;
- Entrega Impossível — ×2.

A diferença de dificuldade deve produzir mudanças reais de gameplay. Na Fase 1, o nível fácil não utiliza objetos caindo de cima, regra incorporada a partir do feedback dos jogadores.

## Evolução do ranking

A próxima evolução registrada é separar a pontuação em:

- melhor pontuação por fase;
- placar geral baseado na soma das melhores pontuações das seis fases.

A implementação deve preservar o ranking atual e ser feita de forma incremental, sem reconstruir sistemas estáveis.

## Próximas melhorias registradas

- validar placar por fase e placar geral;
- implementar/testar itens colecionáveis, quando esta mecânica for retomada;
- refinar física e colisões;
- melhorar feedback visual e sonoro;
- avaliar contador global de visitantes;
- adicionar melhorias de acessibilidade.

## Boas práticas para novos prompts

1. Fazer uma alteração principal por vez quando o recurso for sensível.
2. Pedir explicitamente para preservar funcionalidades existentes.
3. Evitar reconstruir o jogo inteiro para uma pequena melhoria.
4. Testar desktop e celular após mudanças de interface/controle.
5. Registrar no GitHub o que foi alterado e por quê.
6. Nunca inserir credenciais, tokens, chaves de API ou dados pessoais em prompts ou no repositório público.
7. Marcar como implementada somente uma funcionalidade que tenha sido efetivamente testada.
